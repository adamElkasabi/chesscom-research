## 1. The facade is a real binary transport

Before the binary facade, `Cft = I8(L8,"getBotMove")` and `kft = I8(L8,"getBotMoveFromConfig")` are node-facing adapters. `L8` returns the setup CEE instance. `I8` uses `vft` to queue the operation, map a chess-node hash (or null root) through `gamePointByNode`, and supply the resulting native game-point handle to the corresponding facade method. `hft` detects stale work using root identity or the node's line/move hash.

The adapter checks staleness **before and after** the awaited engine call. Missing game points are logged and return no result. Stale responses are discarded rather than applied to a changed board. It does not catch an engine rejection at this layer. Five additional exact-function checks cover normal, missing-game-point, stale-before, stale-after and rejected-engine scenarios. Thus an empty move can reflect invalidated frontend work, not necessarily a native search failure; `Z5` still does not fall through from its configured branch.

In the shared bundle, `Eit(options)` creates `lit(options)`, then returns methods generated by `Tit(UG(J4,transport))` plus direct model/artifact helpers.

- `J4` is the generated `ExplanationEngineService` descriptor, not a hand-maintained method-name switch.
- `UG` generates clients based on method kind.
- `Tit` adds game-point context only to methods whose `has_gp` option requires it.
- `Xrt` reads per-method options: custom field50001 selects feature/CEE command;50002 is game-point requirement;50003 can hold CEAC-field mapping.
- `lit.handleUnary` serializes the real request descriptor to protobuf bytes, dispatches the feature, then deserializes its real response descriptor. The generated RPC shape by itself does not mean the call uses HTTP; this transport targets the worker.

Exact source spans, decoded method options and binary descriptor hashes are preserved. `service-routing.json` records raw option fields; it is an extraction, not a guessed list of feature IDs.

## 2. Serialized worker queue and completion rules

`nit` starts `new Worker(workerJsPath + '#' + workerWasmPath)`. `o3` queues command/arguments; it posts only the queue head. `l3` advances the queue. There are no per-request IDs in this protocol, so concurrent uncoordinated calls would misassociate results.

`u3` queues `CEE_NewFeature(gamePoint,id,requestBytes)`, records the returned handle, then `CEE_Run(handle)`. At25 retained feature handles it disposes the oldest before creating another. This retention policy differs from our reproduction harness, which immediately disposes each completed feature; neither difference establishes a semantic difference in the tested outputs.

`eit` treats:

- string messages as log notifications;
- `error` as a failed queued command;
- `CEE_Run` messages with `proto` as stream updates, resolving on `is_final`;
- `CEE_LoadCharmModel_done` as its own acknowledgment and checks `success`;
- `retval` as ordinary command completion.

The initial test-harness timeout came from failing to implement the model-specific acknowledgment, not a failed native load. The corrected harness mirrors that branch and retains all failed-attempt context.

## 3. Native glue / memory boundary

Original SRC-0014 glue copies request bytes into linear memory, calls exported `CEE_NewFeature`, and frees the temporary request buffer. `CEE_Run` invokes the native feature asynchronously. The glue's `CEE_LoadCharmModel` separately copies model bytes and UTF-8 key into native memory, calls the native export, then frees temporary buffers and emits its completion object. A successful return and a later model-dependent decision are stronger evidence than merely finding an export name.

The underlying original module-002 WASM is hash-identified; it was not replaced by a small illustrative model or JavaScript imitation. Prior broader WASM structural/function coverage remains the baseline: this chapter explains **selected interfaces and behaviors**, not a new every-function semantic audit.

## 4. Where the assets are chosen

`q6e` / `J6e` select worker JS/WASM paths. The R2 branch is gated by `explanation_engine_r2` and non-dev/non-test context. `m0` chooses normal package version, or staff-configured version/fallback. `h0` selects default/no-SIMD according to the corresponding feature/capability checks. Otherwise a fallback asset directory is used.

The public package embeds normal version1.130.285. This does not let us merge any URL with any archived binary by filename, nor assume staff/default/no-SIMD bytes are identical. The new native tests explicitly identify which old bytes were executed; there was no new worker/WASM download in this focused investigation.

## 5. Namespace safety rules

- Bots metadata personality numbers require `Npt` translation to native bot personalities.
- `BotEngine` values1/2 are not cloud `Engine` values11/12.
- `RunSearch.engineId` identifies a borrowed engine-pool entry, not the cloud enum.
- Native `CeeVersion.ceeVersion` and `uciVersion` are distinct fields.
- `TorchSearchMode.human` is not a personality enum.
- `ModelArch.MAIA=3` and `MAIA3=4` are architecture choices in a config, not the Human mode oneof.
- Model key `m-topaz-jackdaw`, model URL, binary SHA256 and runtime loaded state are four distinct identities. Loading a file under a key does not prove any production config uses that key unless a corresponding config/callsite is observed.

These distinctions prevent the most consequential false conclusions in this subject.
